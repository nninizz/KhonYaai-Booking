## 1. Intent

ผู้จองต้องบอกงานย้ายของให้ครบ (วัน เวลา จุดรับ จุดส่ง ประเภทสิ่งของ) โดยเลือกจุดรับ-ส่งจากรายการสถานที่หรือใช้ตำแหน่งปัจจุบัน เห็นค่าบริการและมัดจำก่อนตัดสินใจ แล้วสร้างการจองที่รอชำระมัดจำ เพื่อส่งต่อให้ ④ เก็บเงิน
feature นี้จบที่การสร้างการจองสถานะ `PENDING_DEPOSIT` และส่งเลขการจองให้หน้าชำระมัดจำ ส่วนการจ่ายเงิน การยกเลิก และการติดตามสถานะเป็นของ feature อื่น
อ้างหลักฐาน: ยังไม่มี PB-xx / EV-xx (ดู Q-03)

## 2. Scope และ Non-goals

In:
- กรอกข้อมูลจอง: วันและเวลานัดหมาย จุดรับ จุดส่ง ประเภทสิ่งของ เล็ก / กลาง / ใหญ่ (REQ-FN-301)
- คำนวณระยะทางจากพิกัดและแสดงค่าบริการรวม มัดจำ และส่วนที่เหลือก่อนยืนยัน (REQ-FN-302)
- เลือกจุดรับและจุดส่งจากรายการสถานที่จำลอง และใช้ตำแหน่งปัจจุบันจากเครื่องของผู้จองเป็นจุดรับได้ (REQ-FN-305, REQ-FN-306)
- รับจองเมื่อเวลานัดหมายห่างอย่างน้อย 4 ชั่วโมง (REQ-FN-303)
- สร้างการจองสถานะ `PENDING_DEPOSIT` เมื่อผู้จองกดยืนยัน แล้วส่งเลขการจองไปหน้าชำระมัดจำของ ④ (REQ-FN-304, REQ-IF-301)

Non-goals:
- การชำระมัดจำ นับถอยหลัง 15 นาที และยกเลิกอัตโนมัติ: เป็นของ ④ (BR-06, BR-08, BR-09)
- การยกเลิกการจองและการคืนหรือริบมัดจำ: เป็นของ ⑥ (BR-03)
- สถานะหลังจ่ายเงิน การส่งงานให้คนขับ คนขับกดรับงานและจบงาน: เป็นของ ④ (`CONFIRMED`) และ ⑤ (BR-07) ตอนนี้ยังไม่มีเจ้าของส่วนส่งงานให้คนขับ (Q-08)
- การเข้าสู่ระบบและการออก token: เป็นของ ② (AS-01)
- การเรียกระบบแผนที่จริงและการแปลงที่อยู่ที่พิมพ์เป็นพิกัด (geocoding): พิกัดมาจากรายการสถานที่จำลองหรือจากเครื่องของผู้จองเท่านั้น ผู้ใช้ไม่กรอกพิกัดเอง ใช้พิกัดที่หน้าเว็บส่งมา คำนวณระยะเส้นตรงเท่านั้น (BR-05, D-03-15)
- การแก้ไขการจองหลังสร้างแล้ว และบริการเสริม เช่น คนช่วยยกของ: ไม่มีใน requirement รุ่นนี้

## 5. Behaviour

- Use case: UC-03 จองรถขนย้าย (ยังไม่มีไฟล์ docs/srs/UC-03.md ดู Q-03)
  - ทางเดินหลัก: ผู้จองเลือกจุดรับ-ส่งจากรายการสถานที่ (หรือกด "ใช้ตำแหน่งปัจจุบัน" ที่จุดรับ) และกรอกวันเวลากับประเภทสิ่งของ → ขอดูราคา → ตรวจราคาและเงื่อนไข → กดยืนยัน → ระบบตรวจ BR-04 และ BR-02 → คำนวณราคา → สร้างการจอง `PENDING_DEPOSIT` → ผู้จองไปหน้าชำระมัดจำของ ④
  - ทางแยก: ข้อมูลไม่ครบ (422) | จองล่วงหน้าน้อยกว่า 4 ชม. (422) | จุดรับกับจุดส่งเป็นจุดเดียวกัน (422) | ระยะใกล้เกินไปจนมัดจำเป็น 0 บาท (422) | ไม่มี token (401) | ผู้จองแก้ข้อมูลใด ๆ แล้วต้องขอดูราคาใหม่ | อ่านตำแหน่งปัจจุบันไม่ได้หรือผู้จองไม่อนุญาต: แจ้งข้อความและให้เลือกจากรายการแทน (AC-03-13)
- วงจรชีวิต: MD-STM-03 | โมเดลข้อมูล: MD-DOM-03 | ลำดับ: MD-SEQ-03 ใน models.md
- กฎธุรกิจ: BR-01, BR-02, BR-04, BR-05 ใน rules.md
- คำที่ใช้ (ยังไม่มี glossary.md): ผู้จอง = ลูกค้า (customer) | มัดจำ = deposit | ส่วนที่เหลือ = remaining (จ่ายคนขับ) | สถานที่ (place) = รายการจำลองใน `mock_db.places` ให้เลือกเป็นจุดรับหรือจุดส่ง | ตำแหน่งปัจจุบัน = พิกัดที่อ่านจากเครื่องของผู้จอง ใช้เป็นจุดรับเท่านั้น | รอชำระมัดจำ = `PENDING_DEPOSIT` | จองสำเร็จ = `CONFIRMED` (ตั้งโดย ④)

### สัญญา API

ทุก endpoint ต้องมี `Authorization: Bearer <token>` (ได้จาก ②) error ใช้ตามข้อตกลงกลุ่ม: 401 ยังไม่ login | 422 ข้อมูลไม่ถูกรูปแบบหรือไม่ผ่านกฎ ส่วน 404 และ 409 ไม่ใช้ใน ③ เพราะไม่มี endpoint ที่หาการจองเดิม

`GET /api/places` รายการสถานที่ให้เลือกเป็นจุดรับ-ส่ง (REQ-FN-305) ตอบ 200 เป็นรายการ `{ "id": 1, "name": "สยามพารากอน", "address": "สยามพารากอน กรุงเทพฯ", "lat": 13.7462, "lng": 100.5347 }` ข้อมูลอยู่ใน `places` ของ `mock_db.py` ไม่มี token หรือ token ผิดตอบ 401 เมื่อผู้จองเลือกสถานที่ หน้าเว็บนำ `address`, `lat`, `lng` ของสถานที่นั้นใส่ในช่อง `pickup_*` หรือ `dropoff_*` ของ body ด้านล่าง

ตำแหน่งปัจจุบันของเครื่อง (REQ-FN-306) หน้าเว็บอ่านพิกัดจากบราวเซอร์แล้วส่งเป็น `pickup_lat`, `pickup_lng` โดย `pickup_address` เป็นข้อความ "ตำแหน่งปัจจุบัน" (AS-04) backend ไม่รู้ว่าพิกัดมาจากที่ไหน ตรวจ BR-04 เหมือนกัน

`POST /api/bookings/quote` ดูราคา ไม่สร้างการจอง (REQ-FN-302)

`POST /api/bookings` ยืนยันและสร้างการจอง (REQ-FN-301 ถึง REQ-FN-304) ทั้งสอง endpoint รับ body เดียวกัน

หน้าจอเปิดใช้ปุ่ม "ยืนยันการจอง" ได้เฉพาะเมื่อมีผลดูราคาล่าสุดที่คำนวณจากข้อมูลปัจจุบันครบทุกช่องแล้ว หากผู้จองแก้จุดรับ จุดส่ง วันเวลา หรือประเภทสิ่งของ ผลดูราคาเดิมต้องถูกล้างและต้องกด "ดูราคา" ใหม่ (AC-03-03) ส่วน backend ไม่มี quote id และคำนวณราคาใหม่จากข้อมูลที่ส่งมายืนยันทุกครั้ง (REQ-DAT-301)

```json
{
  "pickup_address": "สยามพารากอน", "pickup_lat": 13.7462, "pickup_lng": 100.5347,
  "dropoff_address": "เซ็นทรัลเวิลด์", "dropoff_lat": 13.7466, "dropoff_lng": 100.5393,
  "scheduled_at": "2026-11-19T10:00:00",
  "item_size": "MEDIUM"
}
```

body **ไม่มีช่องยอดเงิน** ถ้าส่งมาจะไม่ถูกใช้ (REQ-DAT-301)

| ผล | HTTP | body |
|---|---|---|
| ดูราคาสำเร็จ | 200 | `{ "distance_km": 0.5, "total_price": 5, "deposit_amount": 2, "remaining_amount": 3 }` (ตัวอย่างนี้คำนวณจากพิกัดใน body ด้านบนจริง) ไม่มีเลขการจอง |
| สร้างการจองสำเร็จ | 201 | booking ครบทุกฟิลด์ตามสัญญากับ ④ ในตารางด้านล่าง |
| ไม่มี token หรือ token ผิด | 401 | |
| ข้อมูลไม่ครบ (BR-04) หรือจองล่วงหน้าน้อยกว่า 4 ชม. (BR-02) หรือระยะ 0.0 กม. (D-03-05) หรือมัดจำเป็น 0 บาท (D-03-16) | 422 | `detail` บอกช่องหรือเหตุผล โดย `/quote` และ `/api/bookings` ใช้ข้อความเดียวกันเมื่อมัดจำเป็น 0 บาท คือ "ระยะใกล้เกินไป" |

`/quote` ตรวจ BR-04 และ BR-05 เหมือนกัน แต่ไม่ตรวจ BR-02 จึงแสดงราคาได้แม้เวลานัดหมายห่างน้อยกว่า 4 ชั่วโมง; BR-02 ตรวจเฉพาะตอนยืนยัน

ตัวอย่าง response 201:

```json
{
  "id": 1,
  "user_id": 1,
  "pickup_address": "สยามพารากอน",
  "pickup_lat": 13.7462,
  "pickup_lng": 100.5347,
  "dropoff_address": "เซ็นทรัลเวิลด์",
  "dropoff_lat": 13.7466,
  "dropoff_lng": 100.5393,
  "scheduled_at": "2026-11-19T16:00:00",
  "item_size": "MEDIUM",
  "distance_km": 0.5,
  "total_price": 5,
  "deposit_amount": 2,
  "remaining_amount": 3,
  "status": "PENDING_DEPOSIT",
  "cancel_reason": null,
  "cancelled_at": null,
  "created_at": "2026-11-19T10:20:00"
}
```

ชนิดข้อมูลของ `id`, `user_id` และยอดเงินเป็น `int` บาท; `distance_km` และพิกัดเป็น `number`; `scheduled_at` และ `created_at` เป็น ISO 8601 string ไม่มี timezone; `cancel_reason` และ `cancelled_at` เป็น `null` ตอนสร้างสำเร็จ

### สัญญากับ ④ (REQ-IF-301)

④ อ่านการจองจาก `mock_db.bookings` และใช้ฟิลด์เหล่านี้ ③ ต้องสร้างให้ครบ

| ฟิลด์ | ค่า | ④ ใช้ทำอะไร |
|---|---|---|
| `id` | `mock_db.next_id(mock_db.bookings)` | หาการจอง ส่งต่อไปหน้าชำระมัดจำ |
| `user_id` | `id` ของผู้ที่ login | ตรวจว่าเป็นเจ้าของ (404 ถ้าไม่ใช่) |
| `total_price`, `deposit_amount`, `remaining_amount` | `int` บาท จาก `calc_price()` | แสดงยอดและเก็บเงินตาม `deposit_amount` |
| `status` | `PENDING_DEPOSIT` ตั้งผ่าน `change_status(booking, "PENDING_DEPOSIT", "customer")` | ④ ยอมให้จ่ายเฉพาะสถานะนี้ |
