**BR-01 ถึง BR-07 คือ "กฎข้อ 1–7" ของกลุ่ม (มัดจำ 30%, จองล่วงหน้า 4 ชม., ยกเลิก, ข้อมูลการจอง, 10 บาท/กม., วิธีจ่าย, สถานะติดตาม) ไม่มีข้อใดตกที่ ①** ไฟล์นี้จึงใช้รหัส BR-RG-nn ของ ① เอง เพื่อไม่ให้ชนกับเลขของกลุ่ม
BR-RG-01 ถึง BR-RG-06 และ BR-RG-10 **AI เสนอเอง** ไม่มีต้นทางในกฎของกลุ่ม; ทีมยืนยันนโยบาย password ใน BR-RG-04 แล้ว ส่วนข้ออื่นยังรอทีม/PO (Q-06) BR-RG-07 ถึง BR-RG-09 มาจากไฟล์ภาพรวม (โครงข้อมูลและบทบาท ②)
AI ห้ามเปลี่ยนตัวเลขและข้อความในไฟล์นี้ ถ้าเห็นว่าขัดกับ spec ให้ถาม หาก spec.md กับไฟล์นี้ขัดกัน ให้ถือ spec.md เป็นหลักและบันทึกเป็น Q-xx
กฎ password อยู่ที่ `backend/app/register/schemas.py` (ความยาวขั้นต่ำ `MIN_PASSWORD_LEN = 8` และต้องมีตัวพิมพ์ใหญ่/เล็ก) ที่เดียว ข้อความ error อยู่ใน `schemas.py` และ handler 422 ใน `router.py`

ข้อความ error ทั้งหมด **ต้องตรงทุกตัวอักษร** และใช้ซ้ำใน frontend (`validators.js`)

## BR-RG-01 ชื่อ (`name`) (Decision Table)

ตัดช่องว่างหัวท้ายก่อน แล้วตรวจ ค่าที่เก็บคือค่าหลังตัด ฟิลด์ที่ขาด (ไม่มีคีย์ในคำขอ) ถือว่าว่าง
เงื่อนไขอ่านจากบนลงล่าง แถวแรกที่ตรงคือแถวที่ใช้

| แถว | ค่าที่ส่งมา | ผล | หมายเหตุ |
|---|---|---|---|
| R1 | ขาดฟิลด์ / `""` / มีแต่ช่องว่าง เช่น `"   "` | 422 "ห้ามเว้นว่าง" | AC-01-06, AC-01-10 |
| R2 | มีตัวอักษรอย่างน้อยหนึ่งตัว เช่น `"สมชาย"` | ผ่าน | AC-01-01 |
| R3 | มีช่องว่างหัวท้าย เช่น `"  สมชาย  "` | ผ่าน เก็บเป็น `"สมชาย"` | |

## BR-RG-02 อีเมล (`email`) (Decision Table)

รูปแบบ `ชื่อ@โดเมน.ส่วนท้าย` ต้องมี `@` หนึ่งตัวพอดี ส่วนหน้า `@` ไม่ว่าง ส่วนหลัง `@` ต้องมีจุดและมีตัวอักษรทั้งสองข้างของจุด และไม่มีช่องว่างเลย (นิพจน์ `^[^@\s]+@[^@\s]+\.[^@\s]+$`) หลังตรวจผ่านแปลงเป็นตัวพิมพ์เล็กทั้งหมดก่อนตรวจซ้ำ (BR-RG-05) และก่อนเก็บ
ตัดช่องว่างหัวท้ายก่อนตรวจ

| แถว | ค่าที่ส่งมา | ผล | หมายเหตุ |
|---|---|---|---|
| R1 | ขาดฟิลด์ / `""` / มีแต่ช่องว่าง | 422 "ห้ามเว้นว่าง" | AC-01-10 |
| R2 | `abc` (ไม่มี `@`) | 422 "รูปแบบอีเมลไม่ถูกต้อง" | AC-01-07 |
| R3 | `a@mail` (ไม่มีจุดหลัง `@`) | 422 "รูปแบบอีเมลไม่ถูกต้อง" | |
| R4 | `a b@mail.com` (มีช่องว่างตรงกลาง) | 422 "รูปแบบอีเมลไม่ถูกต้อง" | |
| R5 | `Som@Mail.com` | ผ่าน เก็บและตอบเป็น `som@mail.com` | AC-01-02 |

## BR-RG-03 เบอร์โทร (`phone`) (Decision Table)

ลบ `-` และช่องว่างทุกตัวออกก่อน แล้วต้องเป็นตัวเลข 10 หลักเท่านั้น และตัวแรกเป็น `0` (นิพจน์ `^0\d{9}$`) ค่าที่เก็บและตอบคือค่าหลังลบ

| แถว | ค่าที่ส่งมา | ผล | หมายเหตุ |
|---|---|---|---|
| R1 | ขาดฟิลด์ / `""` / มีแต่ช่องว่าง | 422 "ห้ามเว้นว่าง" | AC-01-10 |
| R2 | `0812345678` | ผ่าน | AC-01-01 |
| R3 | `081-234-5678` หรือ `089-999 9999` | ผ่าน เก็บเป็น `0812345678` / `0899999999` | AC-01-08 |
| R4 | `123` (สั้นเกินไป) | 422 "เบอร์โทรต้องเป็นตัวเลข 10 หลัก ขึ้นต้นด้วย 0" | AC-01-08 |
| R5 | `812345678` (9 หลัก) หรือ `08123456789` (11 หลัก) | 422 "เบอร์โทรต้องเป็นตัวเลข 10 หลัก ขึ้นต้นด้วย 0" | |
| R6 | `1812345678` (ไม่ขึ้นต้น 0) | 422 "เบอร์โทรต้องเป็นตัวเลข 10 หลัก ขึ้นต้นด้วย 0" | |
| R7 | `08123abcde` (มีตัวอักษร) | 422 "เบอร์โทรต้องเป็นตัวเลข 10 หลัก ขึ้นต้นด้วย 0" | |

## BR-RG-04 รหัสผ่าน (`password`) (Decision Table)

รหัสผ่านของทุกบัญชีใน `users` ต้องผ่านกฎนี้ **ไม่ตัดช่องว่าง** ความยาวนับเป็นจำนวนตัวอักษร ยาวอย่างน้อย 8 ตัว และต้องมีตัวอักษรภาษาอังกฤษพิมพ์ใหญ่อย่างน้อยหนึ่งตัว (`A-Z`) กับพิมพ์เล็กอย่างน้อยหนึ่งตัว (`a-z`) ตัวเลขและสัญลักษณ์อนุญาตแต่ไม่บังคับ ฟิลด์ที่ขาดถือว่าว่าง
เมื่อข้อมูลผ่าน validation ให้เก็บค่า password ตรงตามที่รับมาใน `users.password` ตาม D-01-02 เพื่อให้ตรงกับ Auth ปัจจุบัน; ห้ามส่ง password กลับใน response หรือเขียนลง log (REQ-PRV-101, BR-RG-09)
รหัสผ่าน **ห้ามปรากฏใน response ใด ๆ** รวม response 422 (BR-RG-09)

| แถว | ค่าที่ส่งมา | ผล | หมายเหตุ |
|---|---|---|---|
| R1 | ขาดฟิลด์ / `""` | 422 "ห้ามเว้นว่าง" | AC-01-10 |
| R2 | สั้นกว่า 8 ตัวอักษร หรือไม่มีตัวพิมพ์ใหญ่อย่างน้อยหนึ่งตัว หรือไม่มีตัวพิมพ์เล็กอย่างน้อยหนึ่งตัว เช่น `Abc1234`, `abcdefgh`, `ABCDEFGH` | 422 "รหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร และมีทั้งตัวพิมพ์ใหญ่กับตัวพิมพ์เล็ก" | AC-01-09 |
| R3 | ยาวอย่างน้อย 8 ตัว มีตัวพิมพ์ใหญ่และเล็ก เช่น `Abcd1234` | ผ่าน | AC-01-01 |

## BR-RG-05 อีเมลไม่ซ้ำ (ข้อความ)

หลังรูปแบบผ่านและแปลงเป็นตัวพิมพ์เล็กแล้ว อีเมลต้องไม่ซ้ำกับผู้ใช้ใด ๆ ใน `users` (รวมผู้ใช้ตัวอย่าง `test@mail.com`) การเทียบไม่แยกตัวพิมพ์ใหญ่เล็ก
ถ้าซ้ำ: 409 `{"detail": "อีเมลนี้ถูกใช้สมัครแล้ว", "field": "email"}` ไม่เพิ่มแถวใน `users` (AC-01-03)
ตัวอย่าง: มี `test@mail.com` อยู่แล้ว ส่ง `TEST@Mail.com` → 409

## BR-RG-06 เบอร์ไม่ซ้ำ (ข้อความ)

หลังลบ `-` และช่องว่างแล้ว เบอร์ต้องไม่ซ้ำกับผู้ใช้ใด ๆ ใน `users`
ถ้าซ้ำ: 409 `{"detail": "เบอร์โทรนี้ถูกใช้สมัครแล้ว", "field": "phone"}` ไม่เพิ่มแถวใน `users` (AC-01-04)
ตัวอย่าง: มี `0812345678` อยู่แล้ว ส่ง `081-234-5678` → 409

## BR-RG-07 รหัสผู้ใช้ (`id`) (ข้อความ)

ผู้ใช้ใหม่ได้ `id` = เลขสูงสุดของ `id` ใน `users` + 1 (AC-01-11) ผู้ใช้ไม่ต้องส่ง `id` มา
ตัวอย่าง: `users` มี id 1 และ 2 → ผู้ใช้ใหม่ได้ id 3 · `users` มีแค่ผู้ใช้ตัวอย่าง (id 1) → ผู้ใช้ใหม่ได้ id 2

## BR-RG-08 สถานะยืนยันตัวตน (`is_verified`) (ข้อความ)

ผู้ใช้ที่สมัครใหม่ต้องมี `is_verified = False` เสมอ ไม่รับค่านี้จากคำขอ ② เป็น feature เดียวที่เปลี่ยนเป็น `True` หลัง OTP ทางเบอร์โทรถูก (AS-02) ① ไม่เปลี่ยนค่านี้ในทุกกรณี (AC-01-01) หลังสมัคร ① ส่งผู้ใช้ไปหน้า `/login` ของ ②; ② รับ email/password และเริ่ม OTP สำหรับบัญชีที่ยังไม่ยืนยัน
ตัวอย่าง: หลัง ① สร้างผู้ใช้ใหม่ ค่า `is_verified` เป็น `False`; เมื่อ OTP ถูกต้อง ② จึงเปลี่ยนเป็น `True` โดย ① ไม่เปลี่ยนค่านี้เอง

## BR-RG-09 สิ่งที่ห้ามอยู่ใน response (ข้อความ)

ทุก response ของ `POST /api/auth/register` (201, 409, 422) **ห้ามมี** `password` ห้ามมี token และห้ามสะท้อนค่าที่ผู้ใช้ส่งมา (คีย์ `input` ของ 422 มาตรฐาน FastAPI ต้องถูกตัดออก) (AC-01-01, AC-01-09)
response 201 มีเฉพาะ `id, name, email, phone, is_verified`
ห้ามเขียนรหัสผ่านลง log
ตัวอย่าง: request ที่มี `password` ผิดกฎได้ 422 ซึ่งมี `loc` และ `msg` แต่ไม่มี `input` หรือค่า password; response 201 มีเฉพาะฟิลด์ที่กำหนดและไม่มี password/token

## BR-RG-10 ลำดับการตรวจและการแจ้ง (Decision Table)

เงื่อนไขอ่านจากบนลงล่าง แถวแรกที่ตรงคือแถวที่ใช้ แจ้งผลเพียงช่องเดียวต่อครั้งสำหรับ 409

| แถว | รูปแบบทุกช่องถูก | อีเมลซ้ำ | เบอร์ซ้ำ | ผล | หมายเหตุ |
|---|---|---|---|---|---|
| R1 | ไม่ | ใดก็ได้ | ใดก็ได้ | 422 ทุกช่องที่ผิด (ยังไม่ตรวจซ้ำ) | AC-01-06 ถึง AC-01-10 |
| R2 | ใช่ | ซ้ำ | ใดก็ได้ | 409 `field = "email"` | AC-01-03, AC-01-05 |
| R3 | ใช่ | ไม่ซ้ำ | ซ้ำ | 409 `field = "phone"` | AC-01-04 |
| R4 | ใช่ | ไม่ซ้ำ | ไม่ซ้ำ | 201 สร้างผู้ใช้ | AC-01-01 |

ตัวอย่าง: เมื่อทุกช่องถูกต้องและทั้งอีเมลกับเบอร์ซ้ำ ให้ตอบ 409 เฉพาะ `field = "email"`; ถ้ารูปแบบเบอร์ผิด ให้ตอบ 422 ก่อนตรวจอีเมลซ้ำ
